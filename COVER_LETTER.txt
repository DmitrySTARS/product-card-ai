СОПРОВОДИТЕЛЬНОЕ СООБЩЕНИЕ

Добрый день!

Высылаю выполненное тестовое задание: прототип AI-помощника для подготовки
карточек товаров (контрольно-измерительные приборы).


ЧТО РЕАЛИЗОВАНО

Сервис принимает JSON с данными о приборе и собирает черновик карточки товара:
SEO-заголовок, SEO-описание, список характеристик, поисковые запросы и
коммерческий блок для менеджера. Есть командная строка, локальная веб-форма и
выгрузка в виде текста, Markdown или JSON.

Поддерживаются провайдеры OpenAI и Anthropic. По умолчанию включён
offline-провайдер: детерминированная сборка карточки без обращения к LLM,
чтобы прототип запускался и проверялся без API-ключа.

Внешних зависимостей нет, используется только стандартная библиотека
Python 3.10+. Запуск и примеры описаны в README, готовые выгрузки по двум
товарам лежат в папке examples.


ПРИНЯТЫЕ РЕШЕНИЯ

1) Автопроверка вместо доверия промпту. После генерации код извлекает все
   числовые значения из результата и сверяет их с числами во входных данных.
   Любое число без подтверждения в источнике попадает в предупреждения.

2) Пробелы находит код, а не модель. Модуль validation.py сам определяет
   отсутствующие поля и типовые характеристики КИП, передаёт их в промпт
   и принудительно дописывает в список недостающих данных.

3) Offline-провайдер позволяет запускать прототип без ключа и покрывать его
   тестами детерминированно. Это нижняя граница качества, с которой
   сравнивается работа настоящей LLM.

4) Без внешних зависимостей. HTTP на urllib, веб на http.server,
   тесты на unittest: критерий оценки включает простоту запуска.

5) Температура 0.2: задача про точность, а не про вариативность.


СЛОЖНОСТИ

- Основная сложность: добиться, чтобы модель не выдумывала характеристики.
  Промпт этого не гарантирует, поэтому автопроверка числовых значений
  реализована отдельно в pipeline.py. Для текстовых утверждений без чисел
  такой проверки пока нет, это описано в ограничениях.

- Формат ответа модели нестабилен: OpenAI поддерживает JSON-режим, Anthropic
  нет. Сделан запасной путь: если модель обернула ответ в кодовый блок,
  обёртка снимается, а из текста вырезается первый сбалансированный
  JSON-объект.


ОГРАНИЧЕНИЯ И ПЛАН УЛУЧШЕНИЙ

Полный список приведён в конце README. Главные пункты: автопроверка ловит
выдуманные числа, но не выдуманные формулировки; длина SEO-описания
проверяется, но не исправляется автоматически; нет кэша и пакетной обработки.
